## Settings › Display preferences

`src/app/preferences.ts` stores `{textSize, motion, terminalFontSize}` under one `localStorage` key. Values are validated on read, and storage failures fall back to defaults. It applies them as `data-text-size` and `data-motion` on `<html>` before first render (`main.tsx`). Per 0002 §10 these settings hold no content, so they survive sign-out (the logout and draft clearing paths do not touch the key). The terminal reads its initial font size from the preference. Tests: `preferences.test.ts`, `DisplayPreferences.test.tsx`, and `a11y.spec.ts` (persists across reload; stored keys are exactly the three settings).

## Limits and follow-ups

- **Text size.** Scaling covers the shared tokens only. About 108 hard-coded `px` font sizes in feature stylesheets do not scale yet. Converting them is feature-owned styling work beyond this acceptance.
- **Live supervisor.** Live `/supervisor` shows the compatibility gate against E0 (see 09). Follow-up `steady-cascade-45.12.1` relaxes the exact-limit check to accept advertised capability limits that are lower.
- **Final-bundle live rerun.** It could not run because the E0 stack is gone (see above). The live evidence is from bundle `419e9f33…`, which differs from final source by one Playbooks CSS rule that the fixture suite verifies.
- **Small 320 nits.** The "Supervisor" bottom-nav label overflows its cell by about 5px at 320, with no page overflow.
