# V1 interactive terminal port

The Agents output panel uses the working v1 xterm 6.0.0 renderer and fit addon 0.11.0, theme, focus rules and touch scrolling from `agent-queue2/dashboard`. Full alternate-screen ANSI semantics are preserved. On phones text remains 14px with an internally pannable minimum 80-column screen; the existing session/back/Details composition stays intact.

The transport uses existing authenticated v2 TerminalInfo, Watch/tail, control/renew/release, finite input receipts and resize APIs. Only an explicitly acquired, worker-acknowledged, current controller lease enables stdin and shared resize. Input sends at most 4096 bytes per operation, with a bounded 16KiB volatile queue, serialized receipt confirmation and no byte replay. Uncertain delivery pauses subsequent input across reconnect/view switches. Watch reconnect does not acquire control or launch a process. Output gaps reset the renderer and remain disclosed; resident output is always labelled incomplete. OSC clipboard and remote links are blocked. Transcript retains the earlier literal tail reader.

`pnpm test src/api/interactiveTerminalClient.test.ts`: 3 passed (1.10s). `pnpm typecheck`: passed. `scripts/probe-terminal-port.mjs` exercised the actual xterm DOM, alternate screen, explicit control, typed `hello` + Enter, resize and release at 1440/390/320. All captures were inspected: one large terminal, readable phone text, local horizontal pan and reachable control keys; no page overflow or browser errors. Phone controls were compacted after the first screenshot review. A probe-only stale Release locator was corrected after moving that control to the phone key strip.

**The browser wire is explicitly synthetic source-dev evidence.** Existing session metadata came from read-only daemon GETs; all terminal operations were intercepted by the labelled fixture and never reached canonical state. This proves the port's renderer/interaction/layout, not actual worker delivery. The real interactive tmux/worker join and production composition remain integration work. No Shell/provider strip changes, backend schema changes or new service.
