# G10 — Agents operations views

Task `steady-cascade-45.11`, implemented November 4, 2026. This increment adds Health, Waits, Notifications and Profile views to the Agents Details drawer, extends the usage and cost panel, and freezes the terminal on disconnect. Every view reads its data only while it is open, and each one renders AQ server facts or a short "not reported" or "unavailable" note. Several facts depend on server reads that are out of scope here (H2, H3, H4, H6, H7, F4). The dashboard shows them as unavailable and does not invent them; they are listed in the follow-up below. **Full-page acceptance against 08 and 11, and G11 visual/WCAG sign-off, remain open.**

## Delivered behavior

- **Composition.** `Agents.tsx:437` renders `OperationsNav` (`operations/OperationsViews.tsx:13`) inside the existing Details drawer. The drawer has five views: Overview (the existing details and usage), Health, Waits, Notifications and Profile. Only the selected view mounts and reads. The terminal, footer and composer composition from 08 and 11 is unchanged. On phone, the drawer is a bottom sheet opened from More → Session details.
- **Health (U12/S4).** `operations/HealthView.tsx:16` lists heartbeat, provider output, semantic progress and wait observation as separate cards, each with its own time or a "not reported" note. Stall state is reported as unavailable, and no rung, evidence or quarantine scope is shown. The nudge form (`HealthView.tsx:43`) sends `session.nudge` through `actionRequest`, using a frozen intent with a stable operation id (`operations/nudge.ts`). After an unknown outcome it offers "Re-send same nudge" with identical bytes, and "Check outcome" as a lookup. The form never writes to the terminal.
  - States are distinct: queued, deferred (a human holds the pane), unknown, unsupported (no `session.nudge` permission or no generation) and not sent (`nudge.ts:28`).
  - **Delivered is never shown, because this AQ server reports no nudge delivery observation.** Showing it would invent a fact. It is part of the follow-up.
- **Usage and cost (U12/S3).** `SessionUsage.tsx:18` keeps reported, estimated and unknown values distinct.
  - Unknown renders as "Unknown · <reason>", never 0 or $0.
  - Cost basis shows the currency, rate card and allocation policy refs.
  - Flat subscriptions are labelled as not costed.
  - Completeness (complete, incomplete with a reason, unknown) is stated.
  - Task lineage totals are "Unavailable on this AQ server" (`SessionUsage.tsx:62`).
- **Waits (U13).** `src/api/adapters/waits.ts` adapts `/api/waits` and `/api/waits/{id}`. `operations/WaitsView.tsx:16` lists the registered waits for this attempt. Inspecting one (`WaitsView.tsx:46`) shows:
  - the predicate;
  - the phase and revision;
  - the wait generation and the continuation generation;
  - the deadline policy and next check;
  - the admission blocker;
  - lifecycle: warm, parked, retained hibernation, resume pending or running (`waits.ts:58`);
  - released compute (with its parking receipt) and protected disk (with its parking report), shown separately (`waits.ts:60-61`);
  - per-condition state with verified source and result refs;
  - a dependency's requirement (resolved versus producer success), shown separately (`waits.ts:34-40`);
  - a manual early resume, labelled "resumed before its conditions resolved";
  - the note "Cancelling a wait does not cancel the task."

  A server without wait inspection (404, 405 or 501) shows "Waits unavailable on this AQ server".
- **Notifications (U14).** `operations/NotificationsView.tsx:15` lists this project's notifications. Message, route, attempts, duplicate-risk retries, transport receipt (`adapters/notifications.ts:58`), delivery state and acknowledgment are each shown as separate facts. A missing route reads "No external route recorded for this message".
  - An unknown delivery offers a retry, which requires a duplicate-risk confirmation.
  - The retry calls `POST /api/notifications/retry` with one operation id per delivery revision, so confirming again repeats the same retry.
  - A recorded retry shows the possible-duplicate disposition.
  - No webhook secret is read or rendered; the test asserts this.
  - If `notifications.read` is not offered, the view shows "Notifications unavailable: <reason>" and reads nothing.
- **Terminal reconnect (U11).** After a disconnect:
  - **Frozen input.** `interactiveTerminalClient.ts:150-156` drops the lease, the queue and connected state. `InteractiveTerminal.tsx:69-74` copies the visible xterm rows (`terminal/terminalSnapshot.ts`) into a figure labelled "Last observation" (`InteractiveTerminal.tsx:148`), with a caption saying output after this point was not observed.
  - **Same identity and epoch.** The client reports its `{terminal, session_revision}` binding, and reconnect passes it back as `expect` (`interactiveTerminalClient.ts:12-48`). If the epoch or revision changed, it reports "Terminal epoch changed" and does not watch.
  - **Watch-only replay.** Reconnect re-reads the same terminal and replays its retained tail as a watcher. It never relaunches and never takes control; Take control stays a separate, explicit action.
  - **Gaps.** Retained-tail gaps and sequence discontinuities show as "Output gap — screen restarted" or "Output not retained" (`interactiveTerminalClient.ts:135-140`). The unobserved interval while disconnected is stated in the frozen caption.
  - **Phone status row.** On phone, a disconnect message takes its own toolbar row, as a lease line already does, so it never overruns main's text-size controls (`InteractiveTerminal.module.css`, `.controls[data-disconnected]`).
  - **Remaining gap.** There is no H7 snapshot endpoint, so reconnect replays the retained tail from sequence 0 rather than restoring a server snapshot.
- **Profile (U9).** `OperationsViews.tsx:20` shows the provider, model and harness, the profile revisions and the effective permissions. Instruction provenance and requested permissions are "not reported by this AQ server", so effective permissions cannot be compared with the request. No secrets are read.

Shared files touched:
- `Agents.tsx`: drawer wiring only.
- `src/api/wire/proposed.ts`: types for the wait inspection reads.
- `src/api/adapters/inspection.ts`: session fields the views consume.
- `interactiveTerminalClient.ts`: the reconnect binding.
- `tests/agents-drawers.spec.ts` and `tests/live/agents-focus.spec.ts`: the Permissions list moved into Profile.

There are no route, shell or capability changes.
