# Global supervisor conversation foundation

References inspected directly: `04-supervisor-chat.png`, `09-supervisor-full-desktop.png`, `12-supervisor-mobile.png`, product specification 0002 section 5 and the visual acceptance rules. The approved source subset is the full-page global conversation: readable message history, human message bubbles, server-derived admission state and timestamps, bounded history paging, and a text composer. Docked presentation is deferred until the shell can share the same draft, collection and reading position; no second dock-specific conversation is introduced.

The feature consumes the frozen `human-supervisor-conversation-1` API07 contract from backend `e313268`. Public discovery/create/history/receipt examples are copied under `contracts/live/supervisor-conversation/` and exercised directly. Granular `supervisor.history.read@1` enables discovery/history; `supervisor.message.enqueue@1` separately permits enqueue. Legacy live-supervisor capability is not used. Root owns navigation capability wiring.

Discovery identifies one stable global conversation. Project scope is never sent to its mailbox routes, and changing the selected project retains the loaded conversation and draft. Runtime is explicitly unavailable with null binding; messages can be durably queued for a future central adapter. A queued message is never presented as delivered, reasoned about, performed work, an assistant reply or a worker-routing fallback.

The composer accepts nonblank valid Unicode text, at most 16 KiB of decoded UTF8 and no NUL. Required context and attachment arrays are always empty. No attachment/context controls, uploads, inferred context, typing indicators or synthetic replies are supplied. Desktop Enter sends; Shift+Enter, IME composition and keyCode 229 do not send. Phones retain a labelled Send button.

Before the first POST, the feature freezes independent operation/message UUIDs, the exact conversation revision, original decoded body and canonical request bytes. Request and body digests are checked independently against receipts. An uncertain transport/error response locks that intent; only a body-free status GET or explicit retry of the exact original POST is offered. Lookup 404 does not prove the earlier write finished. Only a typed queued/not-queued receipt permits another intent or deliberate revision. URLs retain operation/message IDs, never body text. After reload, the original body is not reconstructed or persisted; retained identifiers support lookup only.

All protected requests use current-principal/authorization/contract query keys. Receipt adaptation checks conversation, original actor, operation, message and both digests; history checks full conversation identity, author, decoded body digest, chronological cursors, direction and page boundaries. Changing an operation reference fences late results. Existing authentication/authorization and contract integrity fences clear private UI state; this feature does not change SessionProvider. A new authentication context remounts the conversation state.

Reads and responses are finite, same-origin, no-store, abortable and bounded to 256 KiB/six seconds. There are no automatic mailbox writes or mutation retries. Display history is ephemeral and bounded to 64 loaded messages; older/newer records are read through server cursors. Refreshing while the reader has moved up preserves position and offers an explicit new-message marker. The UI does not maintain a second authoritative message database or store bodies in browser storage.

Source checks: 30 focused tests passed in 4.00 seconds across adapter, frozen public examples, bounded client and UI behavior; the exact `pnpm exec tsc -b` command (including tests) and diff checks passed. Coverage includes project/draft preservation, one-send double-click protection, lost-response/exact-retry bytes, pure lookup, typed refusal, 401/403 private-state clearing, cross-operation late completion, cursor ordering, author/conversation/body integrity, response bounds, IME and reader position. Root's composed responsive candidate passed 464 tests in 21.33 seconds, complete TypeScript checking and a production build (564 ms, 29 assets, no mock leakage). Actual acceptance of the bounded full-page subset is recorded below.

Deferred differences: dock/full shared presentation and return location, attachments/context references, result evidence cards, supervisor runtime binding/replies, feedback-task proposals, real mobile OS keyboard behavior and complete Supervisor-page acceptance. None are inferred from mailbox admission.

Independent review followup: an old rejected asynchronous preparation is fenced by its preparation ticket before it can change busy/error state for a newer operation. External operation references reset private pending/receipt state in a layout effect before paint. Regressions hold both the older preparation and newer lookup independently, and verify both 401 and 403 still remove draft/history/actions when a subsequent bootstrap refresh returns 503. These changes are feature-local; the existing global protected-query error latch remains unchanged.
