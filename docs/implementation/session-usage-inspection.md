# Session usage inspection

References inspected directly: `08-agents-focus-desktop.png`, `11-agent-mobile-v2.png`, product design 0002 section 6 and the visual acceptance rules. The delivered source subset is an on-demand accounting section inside existing Session details. The large focused output, compact session switcher, status footer and phone exit remain in place. Opening a session does not read accounting.

The granular `session.usage.read@1` capability enables the read only when an independently authorized Session detail provides `observation_binding`. Absent/null legacy bindings remain unavailable. The adapter checks project, task, attempt and session IDs against the detail, safely normalizes the summary identity's decimal-string generation, and compares every full session identity field. It then compares every numeric observation binding field, including lineage and attempt generation, against the raw usage response. Scope/identity mismatches retain the existing conservative contract fence; no global session policy changed.

`GET /api/observations/sessions/{attempt}/usage` is finite, same-origin, no-store, abortable, limited to 16 KiB and five seconds. It runs only while details is open, with no automatic polling, retry, focus or reconnect read. Query identity includes the complete binding and current authorization context. Closing details unmounts the read and discards its cache; a failed refresh hides previous values. Unsupported schema/variants, unsafe integers and inconsistent known-counter projections are rejected.

Five categories are shown independently; they may overlap and are never summed. Unknown counters retain their reason. Reported subtotals are explicitly partial when the corresponding counter is unknown. Revision zero with null last-recorded time means no accounting projection, not zero usage or free cost. Unknown/not-reported costs stay unknown. Provider charges and non-invoice estimates have distinct labels if ever supplied by the wire contract. Session accounting does not determine account quota, provider health or invoice totals.

Source validation: 63 focused tests passed in 3.06 seconds across the usage adapter/client/component and existing session inspection suites; typecheck passed. Coverage includes all binding fields, stale generations, mismatched remote boot and central authority, unsafe integers, response limits, capability/anchor gating, partial and empty projections, failed refresh clearing and a late response from a previously selected session. An independent read-only review found no blocker.

Production build and actual desktop/phone visual qualification are pending root's integration slot and mounted backend capability. No live visual acceptance or complete Agents-page acceptance is claimed by these source checks. Native full terminal interaction, transcript inspection and accounting completeness remain separate work.
