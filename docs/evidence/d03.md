## What exists

- Shell with rail in spec order (Overview, Supervisor, Work, Results, Decisions, Agents, Playbooks, Knowledge; Settings and identity at the bottom), sticky top area with scope picker (URL `?scope=project:<id>`), search affordance (disabled with an explanation) and account-wide provider usage strip.
- Phone layout below 768px: compact header, wrapped quota, bottom destinations Overview, Results, Supervisor, Agents and More (Work, Decisions, Playbooks, Knowledge, Settings).
- Every spec route, lazy loaded per feature. Each destination is capability-gated: a capability the server does not offer shows its reason and makes no request. Enabled destinations say which work package delivers their content. Unknown paths show a neutral not-found view.
- Provider usage: percent used, window name, reset and freshness per provider; unknown, unavailable or unsupported states render "Usage unavailable", never 0%. Stale values keep their observation age. Multiple windows are disclosed separately, never combined. The preferred window comes from the server. Estimated and partial values are labelled; display rounding never shows a nonzero value as 0% or a sub-limit value as 100%. Ages and staleness advance between polls from the last server time plus monotonic elapsed time (never the local wall clock); a failed or timed-out (15 s) refresh keeps the last values marked stale.
- HTTP client: `X-AQ-Request: 1` on non-GET requests, error-envelope parsing, HTML responses rejected as contract errors, transport failures on mutations flagged as unknown effect. Query keys carry principal, authorization revision and contract version; scope is passed by callers in the key's params (not yet structurally enforced).
- Connection status in the top area (Connected / Disconnected / Sign-in expired) derived from bootstrap and usage refreshes. Heading focus moves only on page changes, not scope changes. On phones the header scrolls away so it cannot obscure focused content; the More menu follows the More button in tab order and Escape returns focus to it.
- Mock harness (`pnpm dev:mock`, `?scenario=`), an on-screen mock banner, and a build-time check that fails if mock code or fixture data reach `dist/`.

## Review

A fresh-context review found 0 Critical, 7 Important and 8 Minor issues. All Important issues were fixed test-first. Deferred minors: mock-banner condition differs from mock startup; windows popover lacks Escape/auto-close and has a 24px toggle; API client edge cases (204, mid-body abort, custom abort reasons, null body); bootstrap 401 retried before showing sign-in; scope not structural in query keys and `?scope=` IDs not validated; no separate FreshnessLabel component and quota polling not yet driven by bootstrap limits; two weak test names/assertions.

## Not done or not claimed

- Manual screen-reader, real-device mobile, Firefox/Safari, 200% text and 400% zoom checks were not run. Automated axe results do not establish conformance.
- Icons, Overview/Work content (D04) and search are absent by design.
- On phones the quota strip is present on every route but scrolls with the page rather than staying pinned.
- Cache clearing on identity change relies on principal-bound query keys; explicit removal is deferred to D04.
