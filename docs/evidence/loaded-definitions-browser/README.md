# Loaded startup definitions: independent visual and actual-owner acceptance

Reference: [`06-playbooks.png`](../../design/06-playbooks.png), product design
section 8 and [visual acceptance](../../design/visual-acceptance.md). Reviewer:
`/root/visual_agents_v2`, November 1, 2026.

The delivered subset is the Definitions tab's loaded startup metadata. It retains
the accepted roster/detail hierarchy, selected row and prominent definition
heading, purpose, immutable pins, entry points and declared dependency references.
The pane describes runtime startup configuration and explicitly does not report
current installation or activation. Runs and unavailable Activations remain
separate destinations. Current catalog discovery, activation management, source
editing, compilation, installation and creation remain deferred; this does not
close the complete Playbooks design.

The frozen positive probe and pinned actual owner fixture passed in 2.89 seconds
(browser 1207ms). The served bootstrap digest exactly matched immutable bundle
`8fe4fa06127cc0f3188bb3bbe45fdd6741cbb395f952d27ec7d7dd29b6b3628c`.
The actual startup artifact had a valid 128-byte definition name, entry name and
dependency alias. Exact artifact/fingerprint/source/compiler/purpose/entry and
declared references were verified against protected owner metadata. No browser
response interception was used. Definitions made zero browser requests to run/admission/binding/status routes;
returning to Runs intentionally made one run-list request. Browser mutations, foreign
requests and page errors were zero. Deep-link reload, 390/320px reflow, mobile
All definitions exit and restored roster focus passed.

Desktop 1440px and phone 390/320px screenshots were inspected independently.
Desktop keeps its roster and distinct detail panels. Phones show one detail;
All definitions remains visible and returns to the selected row. The long title,
entry and dependency alias wrap locally; immutable facts stack on phones and
full digests remain readable. No document horizontal overflow occurred. The
shared mobile header remains tall, and the extreme fixture name takes multiple
lines; neither is claimed as full mobile-shell design completion.

The original phone viewport captures mainly show the deliberately long heading.

assertions or product source. Those added images were inspected to verify the
