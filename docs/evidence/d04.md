## What exists

- **Overview:**
  - Counts that keep unknown as unknown and mark estimates.
  - Needs-attention rows showing reason, impact, age and project, each linking to its exact subject.
  - Work in motion and recent outcomes.
  - "Nothing needs your attention" only after a complete successful read; partial reads warn and failed reads show an error.
- **Work:**
  - A cursor-paged list (25 per page, Load more, total with accuracy) with readiness filter and scope in the URL, and a manual Refresh instead of auto-polling, so rows never move under the reader.
  - Task detail showing the server's readiness explanation, acceptance criteria, dependencies, attempts and distinct delivery facts, polling every 5 s.
  - Desktop shows list and inspector side by side; narrower screens show one pane. Back restores focus to the originating row.
- **Graph:**
  - A lazily loaded chunk with a deterministic layered layout (only dependency and hierarchy edges set the layers) and a 100-node client cap.
  - Distinct dependency, hierarchy and related edges, with server and client omitted counts.
  - Keyboard-reachable node buttons and an equivalent text list of relationships.
  - The root stays fixed, so selecting a node never moves the layout. On phones, Graph and task detail are separate panes, and Back returns from detail to the graph.
- **Agents:**
  - The roster shows task, project, model/harness, authority, reported state with server-time freshness, controller and wait reason, polling every 10 s.
  - Session detail shows profile revisions, permissions and activity. The terminal is plainly marked unavailable (D07) with the server's capability reason.
- **Search:** one native modal dialog for the button, Ctrl/⌘+K and touch. It runs a debounced, scoped query of 2+ characters, groups results by type, supports arrow-key movement and returns focus to Search on close.
- **Shared:**
  - Read-state components: loading, failure, forbidden, neutral 404, contract error, partial, and empty only after success.
  - Scope is a structural element of every scoped query key.
  - Unknown enums render as unsupported and disable actions.
  - Server text is rendered as text, never markup.

## Defects found and fixed during D04

- Detail reads were cached by resource name without the request path, so opening a second task showed the first task's data. The path is now part of every read key, and tests now use production cache timing so they reproduce the bug.
- On phones, the Graph view was unreachable while a task was selected. Narrow screens now treat graph and detail as separate panes.
- The Overview table's narrow-width scroller was not keyboard-focusable (axe). It is now a labelled, focusable region.

## Review

A fresh-context review found 0 Critical issues, 4 Important and 11 Minor. Three minors were re-graded to Important because they made the screen state something false or unusable. All seven, plus one minor the fixes depended on, were fixed test-first:

- **List re-paging on return:** the Work list re-paged itself in the background after returning to Work. It no longer refetches on focus or return; only the Refresh button refetches.
- **Graph cap and layout:**
  - The 100-node cap could drop the root. It now keeps the root and the nodes nearest to it.
  - A NaN comparator mis-ordered unreachable nodes.
  - Cycles could place nodes off the canvas; layer numbers are now compressed.
  - Edges cut by the cap are counted.
- **Focus after Back:** Back did not restore focus from graph nodes or Agents roster rows.
- **Malformed search:** a malformed search response could replace the whole app with the router error screen. Search now has a validating adapter, and contract errors show a "can't read" message instead of "Try again".
- **Unrecognised URL filter:** an unrecognised `?readiness=` value showed "All readiness" while filtering to nothing. It is now ignored.
- **Unrecognised count accuracy:** a count with an accuracy this client doesn't know rendered as exact. It now renders as estimated.
- **Search announcements:** the whole search results area was `aria-live`. Only a result count is announced now.

Deferred minors:
- Closing search returns focus to the Search button rather than the invoking element.
- Graph rows shift when nodes are added, and the graph refetches on window focus.
- A failed Load more shows "Refresh failed" wording.
- The roster poll refetches every loaded page.
- Work in motion has no empty-state wording.
- Some CSS rules are duplicated.
- Three test assertions are weaker than their names.
